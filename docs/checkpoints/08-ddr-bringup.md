# Checkpoint 8: Nexys A7 DDR2 bring-up

Status: in progress. The real board timing and DDR measurements are pending.

## Prepared traffic and measurement path

`checkpoint8_traffic` drives 256 aligned, 16-beat, 128-bit write bursts over a
64 KiB DDR region, then reads and checks every beat. It repeats the sweep while
a second master continually performs single-beat write/read checks in a
disjoint region. The second master is **CPU-like synthetic traffic**: the CPU
itself will reach AXI only after checkpoint 9's cache integration. This
distinction must remain visible in the checkpoint 8 result.

The benchmark counts core clock cycles separately for each write and read
sweep. `checkpoint8_uart_report` repeats a 33-byte `D8BM` version 1 packet at
115200 baud. `scripts/decode_checkpoint8.py` checks the packet's error counts
and converts each 64 KiB sweep to decimal MB/s at the intended 50 MHz core
clock. The board must report zero DMA and CPU-like errors.

The simulation gate is `bash scripts/run_checkpoint8_traffic.sh` on the Ubuntu
Verilator host. It includes the checkpoint 7 fabric and clock crossing, a
backpressured DDR model, two unrelated clock ratios, full data comparison, and
a UART waveform/packet check. This gate does not model MIG calibration or DDR
electrical behavior.

On 2026-09-27, Verilator 5.032 passed both 50/83.3 MHz and 71.4/45.5 MHz
core/model clock cases with zero data and response errors. The checkpoint 7
AXI regression also passed after generalizing the test slave's address index.
These simulated cycle counts are diagnostic only; bandwidth is recorded only
from the real board.

## Board handoff

Target exactly `xc7a100tcsg324-1` (Nexys A7-100T). Use the Digilent
Nexys A7-100T [DDR2 board preset](https://github.com/Digilent/vivado-boards/tree/master/new/board_files/nexys-a7-100t/D.0/1.3) or its MIG pinout, with AXI4 enabled, 128-bit
AXI data, four ID bits, and 128 MiB at the physical window
`0x80000000`–`0x87ffffff`. Digilent's preset describes a 27-bit MIG AXI
address offset. The integration adapter must translate the fabric's 32-bit
physical address to that offset; no wrapped or aliased DDR address is accepted.
The generated `ddr_probe_mig_7series_0_0.veo` and `mig.prj` were inspected on
2026-09-27. The template has 67 ports, all mapped in
`rtl/top/checkpoint8_board_top.sv`. The project file confirms DDR2 at 3077 ps,
4:1 PHY ratio, 100 MHz single-ended system clock, a 200 MHz no-buffer
reference clock, active-low `sys_rst`, 16-bit device data, a 128-bit AXI data
port, 27-bit AXI addresses, and four ID bits. A dedicated 100 MHz to
50/200 MHz PLL supplies the core and reference clocks. The generated MIG
constraints and actual `ui_clk` frequency still need Vivado implementation
evidence.

The board operator can source `scripts/checkpoint8_add_sources.tcl` in the
open Vivado project containing that generated MIG IP. This adds the RTL and
non-DDR XDC and sets `checkpoint8_board_top` as top. The simulation-only
vendor stubs under `tests/board` must never enter the Vivado project.

The board build must use `constraints/checkpoint8_board.xdc` for the clock,
reset, UART TX, and four LEDs, plus the constraints generated by MIG for DDR2.
Program SRAM over JTAG for this bring-up; flash programming belongs to a later
checkpoint. Capture one complete repeated UART packet and run:

```sh
python3 scripts/decode_checkpoint8.py capture.bin
```

After implementation, run `scripts/checkpoint8_reports.tcl` in Vivado on the
project and retain the timing, clock, utilization, interaction, and DRC reports.
Checkpoint 8 passes only after real calibration, readback without errors,
positive 50 MHz setup slack, and measured write/read MB/s with and without
the CPU-like traffic are recorded here.
