# Checkpoint 8: Nexys A7 DDR2 bring-up

Status: in progress for merge readiness. The first board build passed MIG
calibration, 128-bit DDR2 transfer, 50 MHz timing, and bandwidth measurements.
Clock/reset warning remediation requires another Vivado build and board retest
before merging or starting checkpoint 9.

## Prepared traffic and measurement path

`checkpoint8_traffic` drives 256 aligned, 16-beat, 128-bit write bursts over a
64 KiB DDR region, then reads and checks every beat. It repeats the sweep while
a second master continually performs single-beat write/read checks in a
disjoint region. The second master is **CPU-like synthetic traffic**: the CPU
itself will reach AXI only after checkpoint 9's cache integration. This
distinction must remain visible in the checkpoint 8 result.

The benchmark counts core clock cycles separately for each write and read
sweep. `checkpoint8_uart_report` repeats a 33-byte `D8BM` version 1 packet at
115200 baud. `scripts/decode_checkpoint8.py` checks the packet's error counts
and converts each 64 KiB sweep to decimal MB/s at the intended 50 MHz core
clock. The board must report zero DMA and CPU-like errors.

The simulation gate is `bash scripts/run_checkpoint8_traffic.sh` on the Ubuntu
Verilator host. It includes the checkpoint 7 fabric and clock crossing, a
backpressured DDR model, two unrelated clock ratios, full data comparison, and
a UART waveform/packet check. This gate does not model MIG calibration or DDR
electrical behavior.

On 2026-09-27, Verilator 5.032 passed both 50/83.3 MHz and 71.4/45.5 MHz
core/model clock cases with zero data and response errors. The checkpoint 7
AXI regression also passed after generalizing the test slave's address index.
These simulated cycle counts are diagnostic only; bandwidth is recorded only
from the real board.

## Board handoff

Target exactly `xc7a100tcsg324-1` (Nexys A7-100T). Use the Digilent
Nexys A7-100T [DDR2 board preset](https://github.com/Digilent/vivado-boards/tree/master/new/board_files/nexys-a7-100t/D.0/1.3) or its MIG pinout, with AXI4 enabled, 128-bit
AXI data, four ID bits, and 128 MiB at the physical window
`0x80000000`–`0x87ffffff`. Digilent's preset describes a 27-bit MIG AXI
address offset. The integration adapter must translate the fabric's 32-bit
physical address to that offset; no wrapped or aliased DDR address is accepted.
The generated `ddr_probe_mig_7series_0_0.veo` and `mig.prj` were inspected on
2026-09-27. The template has 67 ports. The MIG was created inside
`ddr_probe.bd`, so the board top instantiates the generated block-design
wrapper and exposes its AXI, reset, and UI ports through
`scripts/checkpoint8_prepare_bd.tcl`. The project file confirms DDR2 at 3077 ps,
4:1 PHY ratio, 100 MHz single-ended system clock, a 200 MHz no-buffer
reference clock, active-low `sys_rst`, 16-bit device data, a 128-bit AXI data
port, 27-bit AXI addresses, and four ID bits. A dedicated 100 MHz to
50/200 MHz PLL supplies the core and reference clocks. The routed Vivado clock
report confirms a 50 MHz core clock, 200 MHz reference clock, and 81.25 MHz MIG
`ui_clk`.

The board operator can source `scripts/checkpoint8_add_sources.tcl` and then
`scripts/checkpoint8_prepare_bd.tcl` in the open Vivado project containing
`ddr_probe.bd`. The first adds RTL and non-DDR XDC; the second exposes MIG
signals, validates the block design, generates output products and its wrapper,
then restores `checkpoint8_board_top` as top. The simulation-only vendor stubs
under `tests/board` must never enter the Vivado project. The first synthesis
attempt failed because it tried to instantiate the MIG child directly. After
switching to the block-design wrapper, synthesis and implementation completed.

The board build must use `constraints/checkpoint8_board.xdc` for the clock,
reset, UART TX, and four LEDs, plus the constraints generated by MIG for DDR2.
The first routed implementation completed but reported WNS -5.588 ns. Its
50 MHz core paths had WNS +7.667 ns and MIG 81.25 MHz UI paths had WNS
+2.942 ns; the violations were on the asynchronous clock crossing and reset.
`constraints/checkpoint8_cdc.xdc` bounds both crossing directions to 12 ns
with `set_max_delay -datapath_only`. The subsequent fully routed implementation
reported WNS **+1.316 ns**, TNS 0, 50 MHz core-domain WNS **+8.676 ns**, and
81.25 MHz MIG UI-domain WNS **+4.378 ns**. The default DRC reported no errors;
it reported CFGBVS-1 (configuration-voltage properties absent) and REQP-1709
(buffering on one MIG-generated PLL output) warnings. MIG's generated XDC
defines primary 100 MHz `sys_clk_i` and 200 MHz `clk_ref_i` clocks at scoped
hierarchical pins. TIMING-4, TIMING-6, and TIMING-27 clock methodology warnings
remain. The CDC checker also reports unknown FIFO/reset crossings and six
combinational-reset-before-synchronizer paths. These warnings need engineering
review before treating the build as a reusable timing signoff for later
checkpoints.

The first SRAM bitstream was loaded over JTAG on 2026-09-27; flash programming
belongs to a later checkpoint. It used RTL/constraints through commit `6517b6e`.
LED 0 showed MIG calibration complete, LED 1
showed benchmark completion, LED 2 stayed off (no reported data errors), and
LED 3 blinked (50 MHz-domain heartbeat). A 115200-baud UART capture decoded a
complete repeated `D8BM` packet with these 64 KiB sweep measurements:

| Traffic | Cycles | Write MB/s | Read MB/s |
|---|---:|---:|---:|
| Baseline write | 6,293 | 520.71 | — |
| Baseline read | 9,333 | — | 351.10 |
| CPU-like contention write | 7,546 | 434.24 | — |

The decoder reported **0 DMA errors, 0 CPU-like errors, and 384 CPU-like round
trips**. These are physical DDR2 measurements, while the contention source is

[198-byte raw UART capture](evidence/08-uart-capture.dat) contains six complete,

shows 1,971 of 15,850 slices (12.44%), 5,531 slice LUTs (8.72%), 5,842 slice

## Warning remediation before merge

The initial board pass was recorded as complete too early for merge readiness.
The critical clock and reset findings are being addressed in checkpoint 8:

- The board XDC now specifies CFGBVS=VCCO and CONFIG_VOLTAGE=3.3, matching
  Digilent's [Nexys A7 schematic](https://digilent.com/reference/_media/reference/programmable-logic/nexys-a7/nexys-a7-sch.pdf).
- The late XDC replaces MIG's downstream primary clock with a combinational,
  identity generated clock from the board input, keeping the existing clock
  name and MIG cell/pin constraints. This restores the clock tree's common
  source without editing generated IP files. Generated core and UI clocks
  are queried by their primitive pins instead of auto-derived names.
- `axi_subsystem` registers UI-domain calibration/reset status before it
  drives the common FIFO reset. The board uses PLL LOCKED as its direct
  asynchronous reset source; the reset button resets the PLL itself.
- Each FIFO synchronizes reset release for its pointer/control registers.
  Its payload RAM write process has no asynchronous reset, so the reset no
  longer feeds an unsynchronized storage write-enable.

Verilator 5.032 passed the five checkpoint 7 clock ratios, including calibration
loss and a short external reset pulse, the two checkpoint 8 DDR/UART cases,
and board-top lint after these changes. Vivado implementation and board retest
are still pending. REQP-1709 originates in MIG's PLL-to-UI-MMCM clocking path;
the [AMD MIG clocking architecture](https://docs.amd.com/api/khub/documents/rTaW6qs7YptHTdMLuG0kVA/content)
includes that cascade. Its remaining warning needs a documented review, rather
than a change to the generated clock buffers solely to suppress the warning.
Any remaining CDC findings must be reviewed by endpoint and FIFO protocol.
