# Checkpoint 5: complete RV32I core

Status: complete locally on 2026-09-25. Implementation commit: `6f08b02`. The local OrbStack Ubuntu gate passed. The new CI job will run on the next push; no remote CI result is claimed here.

## Delivered

- Remaining RV32I integer instructions, all six conditional branch forms, JALR, byte and halfword loads/stores, FENCE, ECALL, and EBREAK. Illegal encodings and misaligned targets/accesses trap. The new instruction and data fault inputs propagate precise access faults.
- Decode hazards include all RV32I register writers. Taken control flow and faults flush younger work. A memory-stage fault overrides a younger EX result; a store becomes visible only at WB retirement.
- Separate zero-wait data read and write addresses allow a committing store and younger load to use different words in the same cycle. Byte enables and merged store-to-load forwarding preserve partial writes.
- Directed RV32I instruction coverage, four seeded dependency-heavy randomized programs, and 15 architectural trap cases compare retirement, register writes, memory effects, and trap state against pinned Spike. The trace/UART tests remain in CI.

These are project-authored architecture tests, not a RISC-V certification claim.

## Evidence

On OrbStack Ubuntu with Verilator 5.032, RISC-V GCC 14.2, and pinned Spike 1.1.0:

```text
bash scripts/run_core_slice.sh
PASS: original smoke and branch traces; injected mismatch; forced-hang UART; 256-entry wrap

bash scripts/run_rv32i.sh
PASS: 60 directed architectural events (59 retirements, 1 trap)
PASS: 4 randomized seeds, 447 architectural events each (446 retirements, 1 trap)
PASS: 15 precise exception cases, including instruction/load/store access faults

bash scripts/run_lockstep_smoke.sh --self-test
PASS: matching fixture and rd/store/cause fault injections
```

The fresh Verilator build had no warnings. `git diff --check`, Python syntax checks, shell syntax checks, and the flash layout checker passed.

Two failures found by the new tests were corrected: Spike prints a zero store as `0x0`, so the comparator now derives its byte width from the instruction; Spike reports the faulting PC as `EBREAK` trap value, which the core now matches. The access-fault tests also required handling Spike's absent instruction trace on a fetch fault.

## Scope and next step

The validated interface remains zero-wait and M-mode only. A trap halts simulation after its precise retirement event; privilege CSRs and trap entry are checkpoint 10. Memory latency, caches, and buses are later checkpoints. Checkpoint 6 adds M/A instructions, atomics, CSRs, and fences.
